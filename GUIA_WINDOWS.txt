2. DESCARGAR EL PROYECTO (una sola vez)
------------------------------------------------------------

------------------------------------------------------------
4. ARRANCAR LA PLATAFORMA DE DATOS (Docker)
------------------------------------------------------------
  cd C:\Users\PC\EMBEDVERSEP-shm\plataforma
  powershell -ExecutionPolicy Bypass -File scripts\iniciar.ps1 demo

  - Con "demo" arranca tambien una ESTACION SIMULADA (SD-V2-M) que publica
    un registro cada 10 s. SU SENAL ES SINTETICA: no es una medida del puente.
  - Sin "demo" arrancan solo los servicios (para estaciones reales).
  - La primera vez tarda (descarga imagenes y compila el firmware).

Debe terminar con una tabla de 6 contenedores:
  api, broker, db, grafana, ingesta, pasarela-sim

Medio minuto despues, comprobar que siguen estables:
  docker compose ps
La columna STATUS debe mostrar tiempos que CRECEN ("Up 2 minutes").
Si sale "Restarting" o siempre "Up 2 seconds", ver los registros:
  docker compose logs --tail 40 api
  docker compose logs --tail 40 ingesta
  docker compose logs --tail 20 pasarela-sim


------------------------------------------------------------
5. COMPROBAR QUE LOS DATOS LLEGAN (punta a punta)
------------------------------------------------------------
Desde la carpeta plataforma:

  docker compose exec db psql -U shm -d shm -c "SELECT station_id, count(*), max(timestamp_utc) FROM ventanas GROUP BY 1;"
  docker compose exec db psql -U shm -d shm -c "SELECT count(*) FROM rechazos;"

Correcto si:
  - la primera muestra SD-V2-M y el numero crece al repetirla (1 cada 10 s);
  - la segunda da 0.

Grafana: http://127.0.0.1:3000
  usuario: admin
  contrasena: la linea GRAFANA_ADMIN_PASSWORD del archivo plataforma\.env
  Abrir el tablero "SHM La Novena - operacion" (menu Dashboards).


------------------------------------------------------------
6. CREDENCIALES PARA USAR LA API
------------------------------------------------------------
Desde la carpeta plataforma:

  docker compose exec api python -m shm_plataforma.gestion token --rol lectura --proyecto novena --nombre "Consulta UTS"

El token se muestra UNA sola vez: copiarlo en un lugar seguro.
Cada token ve SOLO su proyecto (--proyecto). Roles: lectura < operador <
ingeniero; "estacion" solo sube sus crudos; "admin" (sin --proyecto) ve todos
los proyectos pero no puede elevar avisos a E3/E4.

Varios proyectos en el mismo servidor: ver proyectos\LEEME.md. Un proyecto
nuevo = una carpeta proyectos\<id>\proyecto.json + volver a ejecutar iniciar.
Si algo de un proyecto esta mal, NO arranca nada; el motivo sale con:
  docker compose logs preparar-db

Probar (en cmd, con curl):
  curl -H "Authorization: Bearer EL_TOKEN" http://127.0.0.1:8000/api/v1/estaciones

O en http://127.0.0.1:8000/api/docs con el boton "Authorize".

las ventanas de la ultima hora. Se actualiza cada 10 s. Es SOLO lectura.

el navegador no lo vuelve a ver. "Desconectar" lo borra.

Si la pagina sale en blanco despues de un git pull: cerrar npm run dev
(Ctrl+C) y volver a arrancarlo.

8. REGLAS DE SEGURIDAD
------------------------------------------------------------

  - No hacer "git add ." a ciegas: revisar "git status" antes de un commit.

9. PROBLEMAS YA VISTOS Y SU SOLUCION
------------------------------------------------------------
"No module named 'shapely'" al generar un modelo
  -> falta tools\venv. Ejecutar:
     powershell -ExecutionPolicy Bypass -File tools\setup_generator.ps1
     y reiniciar npm run dev.

"No se encontro Python 3"
  -> instalar Python de python.org (no de la Store) con "Add to PATH".

git clone / checkout: "invalid path 'C:\Users\PC\Downloads\...inventory.yaml'"
  -> ya corregido en la rama (commit 8b73e5d). Borrar el clon fallido y
     clonar de nuevo:  rmdir /s /q EMBEDVERSEP-shm   y repetir el paso 2.

"pull access denied for shm-novena/servicios"
  -> ya corregido (commit 2f3f33f). Hacer git pull y volver a iniciar.

"El sistema no puede encontrar la ruta especificada" con cd
  -> revisar la ortografia (plataforma, no platafroma) y no empezar la ruta
     con \ (eso va a la raiz del disco).

"git clone" sin repositorio / "https: no se reconoce"
  -> la orden y la URL deben ir en la MISMA linea.

Un puerto ocupado (1883, 3000 u 8000)
  -> otro programa lo usa. Ver cual con:  netstat -ano | findstr :8000
     Los contenedores n8n, mailpit y vision de este PC NO chocan.
